# top-leve-statement

- Starting from .NET 6, your boilerplate code now looks like this:

    >```C#
    >Console.WriteLine("Hello, World!");
    >```

- This is due to the introduction of **top-level statements**, **implicit using directives**, and **global using directives**.

- The most crucial feature in this section is **top-level statements**. This means that the Roslyn compiler automatically generates your `class` and `Main` method with all their elements. However, the namespace itself—which was originally supposed to be the name of your project becomes global.

### Where are your `Main` method and `class`? <!-- markdownlint-disable-line -->

- Your `Main` method is turned into a template and takes this underlying format: `static void <Main>$(String[] args){}`, specifically the `$<Main>` portion. As for your `class`, it is completely auto-generated by the Roslyn compiler.

- To verify this yourself, create a new project and insert the following command:

    > ```C#
    > throw new Exception();
    > ```
    >
    > The output will look like this:
    >
    > ```Plaintext
    > Hello, C#! Unhandled exception. System.Exception: Exception of type 'System.Exception' was thrown.
    > at Program.<Main>$(String[] args) in C:\cs14net10\Chapter01\HelloCS\Program.cs:line 1
    > ```

- as for the auto-generated class will be in the following formate

    > ```c#
    > using static System.Console;
    > partial class Program
    > {
    >  static void <Main>$(String[] args)
    >  {
    >     WriteLine("Top-level functions example");
    >   }
    > }
    > ```

### Where is your The Namespace

- Regarding the Namespace, as mentioned earlier, it becomes global. To confirm this, run the following code (note that the specifics of this code will be explained later):

    > ```C#
    > string name = typeof(Program).Namespace ?? "<null>";
    > Console.WriteLine($"Namespace: {name}");
    >```
    >
    >The output will be:
    >
    >```Plaintext
    >Namespace: <null>
    >```

### where will the code goes inside the generated code

- all the statement variable and control flow you used in the file will be generated inside the generated `Main` function
- defining a method in a top-level program will be also generated inside the generated `Main` method as ***local function*** which unlike the normal standerd method have some special treatment as discuss in [funciton](./funcitons.md)

    > here is how you top-level defined function is generated inside the `main` method
    >
    > ```c#
    > using static System.Console;
    > partial class Program
    > {
    >  static void <Main>$(String[] args) // generated main function 
    >  {
    >     WriteLine("* Top-level functions example");
    >     <<Main>$>g__WhatsMyNamespace|0_0(); // Call the function.
    >     void <<Main>$>g__WhatsMyNamespace|0_0() // Define a local function.
    >     {
    >       WriteLine("Namespace of Program class: {0}",
    >         arg0: typeof(Program).Namespace ?? "null");
    >     }
    >   }
    > }
    > ```

- in order to make the defined method appears on the generated code as standalone method you must use partiale classes aka partial members which will be discussed in the oop section
  1. Add a new class file named Program.Functions.cs. The name of this file does not actually matter, but using this naming convention is sensible. You could name the file Gibberish.cs, and it would have the same behavior.
  2. add the following code in it

    > ```c#
    > using static System.Console;
    > // Do not define a namespace so this class goes in the default empty
    > // namespace just like the auto-generated partial Program class.
    > partial class Program
    > {
    >   static void WhatsMyNamespace() // Define a static function.
    >   {
    >     WriteLine("Namespace of Program class: {0}", typeof(Program).Namespace ?? "null");
    >   }
    > }
    > ```
  
  3. in your top-level program call the method you defined earlier <!-- markdownlint-disable-line -->

    > ```c#
    > using static System.Console;
    > WriteLine("* Top-level functions example");
    > WhatsMyNamespace(); // Call the function.
    > ```

  - the output of using partial classes will be

    > ```c#
    > using static System.Console;
    > partial class Program
    > {
    >   static void <Main>$(String[] args)
    >   {
    >     WriteLine("* Top-level functions example");
    >     WhatsMyNamespace(); // Call the function.
    >   }
    >   static void WhatsMyNamespace() // Define a static function.
    >   {
    >     WriteLine("Namespace of Program class: {0}",
    >       arg0: typeof(Program).Namespace ?? "null");
    >   }
    > }
    > ```

### Rules for Working with Top-Level Statements

- When dealing with top-level statements, you must follow these guidelines:
  - **Single File Limit:** Only one file in your entire project can contain top-level statements.
  - **Placement of `using` Directives:** Any `using` statement must be placed ***at the very top of the file.***
  - **Placement of Classes:** Any custom `class` you create must be placed ***at the bottom of the file***, below the top-level statements.
  - **Method Treatment:** The underlying `Main` method in your file is treated just like a regular, standard method.
  - **Modifiers:** Access modifiers (like `public` and `static`) ***are strictly prohibited at the top level.*** However, using `async` and various attributes is allowed.
  - **Command-Line Arguments:** If you need to pass Command-Line Arguments, you can do so directly. The `args` variable is generated automatically and implicitly by the Roslyn compiler, making it immediately available for use.
