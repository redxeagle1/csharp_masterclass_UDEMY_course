# Partial Members

- Primary Use Case: Partial types exist mainly to separate generated code from handwritten code.
- ***they act like c++ header `.h`***
- each member[except `classes`] has its own implementation but share the same use case and mechanism

### Common Opinions & Best Practices <!-- markdownlint-disable-line MD001 -->

- Tooling/Codegen Justification: Use partials when a framework/tool requires them or to keep autogenerated and manual code separate.
- Avoid As A General Organizational Crutch: Many developers consider splitting a single logical type across files a smell and prefer real refactoring into separate classes
- Practical Exceptions Exist: Teams sometimes use partials pragmatically for large, single-concept types or platform-specific implementations.
- Readable Navigation vs. Encapsulation Tradeoff: Some find partials helpful to visually group related members (e.g., controller actions or large API wrappers), but others warn it reduces discoverability.

### When It’s Reasonable To Use Partials <!-- markdownlint-disable-line MD001 -->

- Auto-Generated Code Separation: Keep generated code and manual edits separate to avoid overwrites.
- Platform/Conditional Implementations: For cross-platform or compilation-target differences.
- Large, Single-Concept Types That Can't Be Split: When a single type legitimately requires many members (e.g., variant/discriminated-union plumbing).
- Controller/API Grouping: Group related endpoints or method groups while keeping one logical type.

### When To Avoid Partials <!-- markdownlint-disable-line MD001 -->

- As a Substitute For Refactoring: If the class is big because of multiple responsibilities, prefer splitting responsibilities into new types
- Scattering State Across Files: Spreading tightly-coupled members across files can harm readability and maintenance.

## Partial classes

- **Partial Classes** allow a class definition to be split across multiple files. This is particularly useful in large projects where different developers might work on different aspects of the same class.
- this is useful when you want to use top-level program while still want the benefits of using class functionality
- another useful use cases
  - Large projects where multiple developers work on the same class.
  - Auto-generated code that needs extension without modification.
  - Keeping related functionalities separate for better organization.
- How to declare then

    ***File: Employee_PersonalDetails.cs***

    ```csharp
    // Partial class declaration
    public partial class Employee
    {
        public string FirstName { get; set; }
        public string LastName { get; set; }
    }
    ```

    ***File: Employee_JobDetails.cs***

    ```cs
    // Another part of the partial class
    public partial class Employee
    {
        public string JobTitle { get; set; }
        public double Salary { get; set; }
    }
    ```

## partial method

- **Partial Methods** enable the declaration of method signatures in one part of a class while allowing the implementation to be optional in another. This can help create cleaner and more maintainable code.
- the compiler deletes it and it calls entirely if unimplemented

- Declaring and Using Partial Methods

    **Basic Syntax**

    ```cs
    public partial class Employee
    {
        // Declaration of a partial method
        partial void OnJobAssigned();
    }
    
    public partial class Employee
    {
        // Optional implementation of the partial method
        partial void OnJobAssigned()
        {
            Console.WriteLine("A new job has been assigned.");
        }
    }
    ```

    **Implementation**
      - Implement the Partial Method (Optional) in another part of the class.
    **Call The Function**

    ```cs
    public partial class Employee
    {
        public void AssignJob(string jobTitle)
        {
            this.JobTitle = jobTitle;
            OnJobAssigned(); // Call the partial method
        }
    }
    ```

- When to Use Partial Methods
  - When defining optional hooks that subclasses may implement.
  - For auto-generated code where an optional implementation can be provided later.
  - Reducing unnecessary code execution if no implementation is needed.
